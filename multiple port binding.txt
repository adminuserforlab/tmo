Case 1:  Multiport port binding error with Kubernetes in Fusion 1.3.23

Hello HAProxy Team,

We are experiencing an issue again with HAProxy Fusion (version 1.3.23). When deploying a LoadBalancer service with multiple ports (8080, 8081, 8082, 8083), the frontends generated by Fusion mix up the ports (in this example 8081 and 8082, but it's random).

Concretely:

We apply this yaml:

```
apiVersion: v1
kind: Pod
metadata:
name: multiport-pod
labels:
app: multiport-app
spec:
containers:
- name: multiport-container
image: nginx:latest
ports:
- containerPort: 8080
name: http1
protocol: TCP
- containerPort: 8081
name: http2
protocol: TCP
- containerPort: 8082
name: http3
protocol: TCP
- containerPort: 8083
name: http4
protocol: TCP
---
apiVersion: v1
kind: Service
metadata:
name: multiport-service
spec:
selector:
app: multiport-app
type: LoadBalancer
ports:
- name: http1
port: 8080
targetPort: 8080
protocol: TCP
- name: http2
port: 8081
targetPort: 8081
protocol: TCP
- name: http3
port: 8082
targetPort: 8082
protocol: TCP
- name: http4
port: 8083
targetPort: 8083
protocol: TCP
```

- Port 8081 bind to :8082 (instead of :8081)
- Port 8082 bind to :8081 (instead of :8082)
- Ports 8080 and 8083 are correct.

We already had this problem in versions 1.3.6 and earlier. At the time, it fixed itself without us understanding why. Then the problem appeared again, so we upgraded to version 1.3.23, the bug is still present.

### What we checked
- Services with a single port are working perfectly, no issues.
- The Kubernetes cluster is OK on the Fusion GUI side, CRDs are applied and the connection is OK
. - All statuses in the Fusion Status page are healthy, no system services show any errors or alerts.
- The generated `ServiceDiscoveryResourceDefinition` object seems correct (see below).
