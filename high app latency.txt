High latency introduced at haproxy

We are using HA Proxy behind F5 LB as Layer 7 with map files to read headers and make pool selection.
F5 LB is only for SSL termination and then sending the traffic to HA Proxy.
The Application latency is only for one of the legacy applications which uses Genuine channels RPC calls from client to server, client uses a thick client application
in their desktop to login and connect to the server in the Datacenter behind the F5 and HA Proxy.
Nature of the Application latency - If the client is having e.g. 100ms network latency, then Application latency will be generally double 200ms, but after adding HA Proxy, it is going almost double of expected 400ms
Application is little chatty and opens several tcp connections per client.
As a workaround we enabled oneconnect on the F5 which reduced the number of TCP connections to the HA Proxy and fixed the issue with the HA Proxy.

Would like to know why we are getting so high latency at the HA Proxy layer (without oneconnect enabled on F5).
