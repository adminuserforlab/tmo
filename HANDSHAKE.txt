Summary of Findings

Intermittent 500 Errors (NOSRV)

These errors are generated by HAProxy when modifying multiple HTTP headers (e.g., client certificate injection).

Likely related to the tune.maxrewrite limit.

Action: Increase tune.maxrewrite value.

SSL Handshake Failures

By default, handshake errors don’t appear in Request Explorer (known bug #2748).

We applied the recommended error-log-format to capture these events — now visible in HAPEE system logs but not yet in Fusion UI.

Status: Expected behavior due to current UI limitation.

TCP Resets

Firewall shows “TCP Reset from Server” with very small byte size (<900 bytes) and 0-second duration.

Packet captures indicate resets occur before HAProxy handles the connection, suggesting a network or OS-level issue.

Action: Capture simultaneous pcaps on both HAProxy and client side to compare behavior.

System & Config Notes

Applied TCP tuning (tcp_max_syn_backlog, somaxconn, netdev_max_backlog) to improve connection handling.

timeout connect (1s) appears too short; client/server/tunnel timeouts are too large — adjustments recommended.

No packet drops observed during testing (nstat and ss outputs clean).
