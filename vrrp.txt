Customer problem: 
We have unfortunately placed a VRRP IP on our "test" HAPEE and would like to relocate this to our PRODUCTION HAPEE instance. We are using Fusion in our environment, have 2 Prod HAPEE and 2 Test HAPEE.

The caveat is that we are currently using this as our Wireguard VPN for ~100 laptops across the country. We cannot afford an outage during this migration. Do you have any creative solutions to us migrating the VRRP from Test to Prod?

Configuration:
udp-lb wireguard
dgram-bind 172.30.255.99:51820 name 172.30.255.99:51820
server wg1 172.30.255.122:51820 check
server wg2 172.30.255.123:51820 check
server wg3 172.30.255.124:51820 check
server wg4 172.30.255.145:51820 check
balance source
option udp-check

Currently for VRRP, the two Test servers communicate and the two prod servers communicate.

Engeer: reply:
I would disable sync to the HAPEE nodes by going into the nodes screen and then checking the boxes next to those nodes and hit pause sync.
Next go to the new prod cluster and add the IP address to the prod cluster.
At this point you're running a duplicate IP address on the network but because it's UDP then unless your systems have some sort of client identification requirements it should still route properly to the same server but the source IP will change.
Now go remove the IP from the VRRP settings on the test cluster and unpause sync.

That's the best I can think of and the only reason it may work is because UDP doesn't care about the connection. However, if your underlying software cares about IP changes then you could face disruption. There's no way to 100% guarantee ip address changes don't disrupt some traffic because ARP can take time to converge. This method should be a small impact but I couldn't guarantee none.
